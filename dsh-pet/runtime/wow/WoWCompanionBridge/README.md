# 魔兽陪伴精灵 · 本机桥接

通信链路、当前版本、存档边界和排查步骤见 [游戏插件与 AIRI 通信说明](../wow-addon-airi-communication.md)。当前桥接版本为 2.19.0，下方保留各功能的开发记录。

## 2.17.0：正式服本地 DB2 只读查询

新增 `retail_query.py`。桌面主进程通过本机文件选择器选定完整的 `retail.sqlite3`，再启动独立的受管只读模式，默认监听 `127.0.0.1:18767`。它与采集端口 18765／18766 分离，继续使用同一份桥接代码和 Python 标准库，不需要新的 MCP 服务或依赖。

只读模式不导入屏幕采集、窗口发现或几何恢复模块，不读取／创建采集配置，也不创建采集线程。陪伴开关关闭、游戏未启动或角色未连接都不影响数据库查询。不会发起模型或语音请求。

受管命令参数：

```text
python server.py --query-only --game retail --port 18767 --database <主进程选择的绝对路径> --query-token <随机64位小写十六进制> --query-instance <随机UUID> --managed-stdin
```

令牌和实例 ID 由主进程为本次子进程生成，不从 renderer 或模型参数读取，也不回传模型。所有 HTTP 请求（含 health）必须带 `X-Wow-Query-Token`，使用恒定时间比较。父进程 stdin 关闭时，该子进程退出，不控制其他采集桥接。

仅开放鉴权后的 `GET /health`（别名 `/api/health`）与 `POST /api/retail/query`；拒绝采集、配置、演示、截图及重连接口。HTTP 不接受数据库路径、任意 SQL、表名或网络地址。查询请求最多 4,096 字节，合法查询的数据库错误以 `outcome:error` 和固定 `errorCode` 返回，不包含路径、SQL 或原始异常。

查询支持：

- `stats`：六类实体的已导出行数和八个支持表的状态，不返回全库 1,130 张表。
- `search`：指定 `item`、`map`、`uimap`、`area`、`spell`、`encounter` 之一，名称或 ID 字面搜索，默认 20 条、最多 50 条，offset 最多 10,000。
- `fetch`：例如 `item:12359`、`map:0`、`spell:133`、`encounter:7`。底层地图 0 是合法 ID，不能与世界地图 ID 混用。

查询使用固定原表白名单、参数化条件及只读不可变连接。源库和旁边的 WAL／SHM 不写入，不创建表或索引；存在未完成 WAL 时拒绝查询。每次查询验证产品 `wow`、必需元数据、八个表和列签名，并受两秒 SQL 进度预算约束。

返回来源为“正式服本地 DB2”，保留构建、语言、真实导出时间、未叠加热修和加密分段提示。数据库里的 `gameRoot` 和选库路径不会进入结果。名称缺失用编号标识；SQL NULL 不造零，法术模板变量不擅自解析为等级数值。地图调谐 ID 不当作旧世探索等级。

详情每条最多 8 KiB，整份结果最多 512 KiB；长字段保留 `result-truncated` 提示，不丢分页行。结果中的内部关联只提供类型与 ID，不编造网页链接。

本次更新源码与测试，未部署游戏插件、修改正式服源库或生成新的 Windows 安装包。

## 2.16.0：只读背包库存

`GET /health` 当前版本为 `2.16.0`。新增独立 `inv` 分片接收，`GET /api/status` 增加必填可空 `inventory`、`inventoryReceivedAt` 和 `inventoryError`。
库存按物品 ID 聚合，只代表随身背包；银行固定未知。分片传输完成与采集完整性分别判断。
每个快照最多 1,000 条、65,536 字节、274 片。两个在途修订受总内存约束，20 分钟超时；身份、内容冲突或过期记录不能替换有效修订。
仅当前角色的实时非演示连接暴露库存。新修订正在接收时隐藏旧库存，避免继续按旧数量计算；切角色、会话、离线和重校准清理状态。
采集时间不能比本机时钟超前超过 120 秒或落后超过 20 分钟。自动备料的界面还会应用更严格的新鲜度规则。
桌面端仅接受 2.16.0 及以上桥接。使用源码更新后需重启桌面端及其受管桥接；本次未触及正在运行的进程。


## 2.15.0：窗口跟随与接收诊断

`GET /health` 的当前版本为 `2.15.0`。新增 `window.py` 和 `connection.py`，须与其他桥接文件一起交付。
根据游戏进程路径、版本目录、窗口句柄、PID 和进程启动时间验证目标，只采集该窗口客户区内的局部像素。
窗口移动或缩放后尝试局部恢复。三个递增且通过协议校验的心跳确认后，才接受并保存新的相对位置与精确格距。
仅冻结的重复帧不能确认校准。未找到窗口时限频查询，同版本多个窗口首次出现时不自动选择。

自动校准保存到配置旁的 `bridge-config.json.calibration.json` 或 `bridge-config-forever.json.calibration.json`，不改变手动起点。
文件只含游戏版本、坐标、窗口尺寸和采样格距，不保存图像、角色内容或进程路径。
修改手动起点后，旧自动校准不再适用。保存失败保留旧文件；恢复仅在当前起点和相对起点附近尝试，不扫描整个桌面。

`GET /api/status` 新增 `connection` 和 `transfers`。分片进度按接收端已验证的唯一片数计算，完成不代表角色心跳仍有效。
`POST /api/reconnect` 仅接受空 JSON 对象，清理未完成接收并重新验证，不请求游戏输入、不触发插件重装。
恢复后按原规则建立新的角色基线，当前临时内容重新接收，桌面端已存历史记录不受影响。
需重启陪伴精灵管理的桥接。若桥接独立启动，须单独重启该进程。

## 2.14.0：场景类型与副本地图标识

接收 v3 快照的可选 `instanceType` 和 `instanceID`，不增加网格尺寸或协议版本。
仅公开确认的类型可区分野外、副本、战场、竞技场和场景战役。缺失字段表示未观测，不能推断为野外。
ID 仅支持正整数或 `null`；正整数必须对应副本或战场类型，不能对应 `none`、`unknown` 或缺失类型。
离线、暂停和数据过期时，当前视图清空观测，保留历史事件事实。
场景信息随最新快照更新，不给原有区域事件重复计数。API 约束见 [协议说明](../WoWCompanion-PROTOCOL.md#scene-observations-2140)。

由桌面端管理的桥接在陪伴精灵正常退出、重启后加载。`GET /health` 返回版本 `2.14.0`。

## 2.13.0：宏导入回执

新增独立 `kind=macro` 帧，由 WoWMacroImport 1.0.0 配合正式服 2.13.0 或无限服 1.10.0 发送。
`GET /api/status` 的 `macroImport` 返回新鲜的输入框状态、请求编号、正文摘要与保存回执。
重复帧不刷新回执或角色心跳。演示、暂停、错误、角色切换和过期状态均不提供有效回执。

`macro_import.py` 是桌面端启动的单次输入流程，通过标准输入接收 JSON，不开放 HTTP 操作接口。
它只向核验过的前台游戏窗口发送固定的打开、粘贴和提交操作，保存后等待插件回执。
`macro_native.py` 使用 Windows SendInput 和剪贴板 API。它不执行宏正文，也不提升进程权限。
安装和操作说明见 [宏导入插件](../WoWMacroImport/README.md)。更新后重启陪伴精灵以加载新桥接。

把 WoW 插件显示在画面上的 WCP1（正式服）或 WCF1（无限服）网格转为本机 JSON 状态和事件，供 魔兽陪伴精灵 桌面二开读取。使用 **Python 3.10+ 标准库**；真实采集需要 Windows，无 pip 依赖。

## 2.12.0：当前地图坐标

接收 v3 快照中的 `px`、`py`。两个字段均缺失表示旧版发送端尚未提供坐标，桥接输出未知值。

字段必须成对出现，均为 `null` 或均为 0～10000 的整数。`1234, 5678` 表示当前 `map` 上的 `12.34, 56.78`。

离线或地图无效时清空坐标。状态页数据过期或采集暂停时，也不把旧坐标作为当前位置输出。历史事件仍保留事件发生时的观察值。

坐标更新不产生新的陪伴事件。64×64 网格、512 字节帧及 504 字节正文限制不变。

更新代码后需重启已运行的桥接。`GET /health` 的版本为 `2.12.0`。由桌面端启动的桥接随桌面端正常退出、再启动而更新。

## 2.11.1：默认紧凑传输码

正式服和无限服新配置均默认每格 1 个物理像素，完整网格占用 **64×64 物理像素**。相较原正式服 128×128 默认网格，面积减少 75%，不减少帧容量或装备资料。

已有 X/Y、格宽与暂停设置不被覆盖。旧校准仍写着 2～12 像素时，如果原格宽不能解码，先直接读取相同原点的 64×64 网格；CRC、灰区与字段校验保持不变。成功后只缓存读取几何，后续每张画面重新解码。

紧凑网格被窗口非整数拉伸时，先在原点附近的 104×104 局部区域尝试 1～1.5 像素格距，预算最多 0.35 秒；再尝试原格宽的局部几何搜索。整轮搜索共享原来的 1.5 秒预算与至少 2 秒重试间隔，不扫描全屏。预览与后续采集裁剪到恢复的网格边界，不把搜索边距当作传输码尺寸。

插件一次性迁移后保留位置，在游戏中 `/reload` 即可加载；也可使用 `/wowc compact`（无限服 `/wowf compact`）立即恢复最小布局。若单像素遭到不可恢复的模糊，仍需修正游戏分辨率或按需将插件和采集格宽都设为 2，校验不会放宽。

## 2.11.0：当前全身装备快照

新增 `kind=gear` 分片，传输角色当前穿戴的全身装备。`GET /api/status` 增加 `equipmentLoadout`（最新完整修订或 null）与独立的 `equipmentLoadoutError`。

- 快照完整列出 1～19 号槽位。`equipped` 携带物品资料，`empty` 表示确认无物品，`unknown` 表示当前无法读取。后两种状态的物品必须为 null。
- 每件物品保存实例链接、名称、类型、品质、装等、等级要求、公开属性及说明文本。套装、附魔、宝石和触发效果保留在说明中，不据此推断效果已激活。
- 每片最多 240 字节，完整快照最多 196608 UTF-8 字节、820 片。单件资料最多 8192 字节。裁剪和缺失必须使用明确的不完整标记。
- 全部槽位只有在整套重组与校验通过后一次替换。未完成的新修订不会与上一套快照拼接。修订 ID 只在当前角色会话内递增，迟到旧修订不能覆盖最新完整快照。
- 独立重组区最多保留 2 套、总计 393216 字节，每套绝对期限 1200 秒。重复分片不延长期限。冲突分片丢弃对应修订，同修订的已完成资料不能被不同内容覆盖。
- 装备快照只能由当前真实角色的在线状态帧接收。账号、角色、会话、采集配置或演示模式改变时清空桥接中的快照。装备分片不刷新角色心跳，不生成获取历史或主动对话事件。
- 原有快速比较、换装提议、CRC 以及自动格距校准保留。魔兽陪伴精灵 把最新完整快照按游戏版本、账号及角色持久保存，并作为聊天中的装备资料。

验证：`python -m unittest discover -v` 覆盖两服真实 Lua 全套快照的像素解码与乱序重组，以及原子替换、空/未知槽位、资料边界、重复修订冲突、过期、内存预算、跨账号/角色/会话隔离和 HTTP 返回。旧的获取记录仍使用原有独立列表与 10 条限制。

## 2.10.0：快速装备询问采集

采集间隔默认 100 毫秒，可配置范围为 100～5000 毫秒。配合游戏插件每 250 毫秒轮播数据帧，完整装备比较能更快到达 魔兽陪伴精灵。已有配置保留原值，更新后将采集间隔设为 100 毫秒。

快采集不跳过像素清晰度、帧校验和 CRC。模糊或遮挡的数据仍会拒绝。

游戏内部渲染尺寸与 Windows 窗口尺寸不同时，网格可能发生非整数拉伸。正常整数网格保持原来的直接采样路径；失败时，桥接在配置位置附近自动搜索 WCP1/WCF1 标识及合法帧长度，分别恢复横向和纵向格距。搜索区域上限为原网格边长的 1.5 倍加每侧 4 格边距（2 像素格对应 208×208 局部图像），单轮搜索预算 1.5 秒，失败后至少 2 秒再试。无需新增配置。

只缓存通过校验的采样几何；每张新画面仍独立执行原有灰区拒绝、CRC 和数据结构验证。缓存失效会立即清除并报告本次采集错误，不会重用旧角色快照。更改坐标、格宽或版本也会清空几何缓存。排序使用黑白像素距离，只帮助寻找采样中心，不修改接收阈值。局部搜索找不到完整网格时，仍需手动校准位置和大小。

角色快照继续使用 v3，WCP1/WCF1 及原有 HTTP 返回结构保持不变。魔兽陪伴精灵 桌面端仍管理桥接，无需另开进程。

验证：使用已有 Python 3.13 与 Lua 5.1 依赖执行 `python -m unittest discover -s . -q`，117 项通过、零跳过。新增覆盖两服默认 100 毫秒、100/5000 包含边界、99/5001 越界、HTTP 边界，以及非均匀双线性拉伸、整数快路径、逐帧缓存校验、失效退避、配置切换、灰区和坏 CRC 拒绝、局部范围与时间预算。原有帧长度、CRC、像素清晰度和跨语言比较检查全部保留。

实机局部图像离线复核：256×256 原始桥接截图裁为生产使用的 208×208 区域后，自动搜索约 0.24 秒；使用缓存几何的逐帧完整校验约 5～7 毫秒。连续三张原始图像均通过严格像素与 CRC 验证。耗时为该机器上的观测值，游戏遮挡、最小化或未显示网格时不会产生有效数据。

## 2.9.0：独立装备属性比较

新增 `kind=cmp` 分片，传递新物品与当前槽位的名称、类型、装等和量化属性，以及可用性、专精匹配和复杂效果标记。桥接只校验并保留事实，不判断装备收益。魔兽陪伴精灵 和游戏插件分别核对相同规则，只有明确提升才发出换装询问。

- `GET /api/status` 增加必填 `equipmentComparisons`（本会话最近 10 条）与独立 `equipmentComparisonError`。
- 比较体最大 4096 UTF-8 字节。每片最多 240 字节，最多 18 片。第 18 片最多 16 字节。
- 比较分片拥有独立的 8 条在途预算、180 秒重组期限和 256 条去重标识，不占用普通装备的在途记录。
- 同一游戏会话内按角色、会话和获取记录 ID 重组；与 `eq` 同 ID 也互不混合。比较记录不能刷新角色心跳。
- 角色/会话/配置/演示切换后清理本机缓存。错误分片只报告比较错误，角色、金币和其他装备流继续工作。
- 同装等的属性提升可以成为提议。`offer` 的装等约束改为新装等不低于旧装等；比较证据仍须由 魔兽陪伴精灵 和插件核对。
- 本页展示新旧物品资料供排错，魔兽陪伴精灵 对应游戏设置页显示分析结果。桥接不保存比较文件，退出后缓存清空。

本轮同时更新正式服插件 2.8.0 / 无限服插件 1.5.0、桥接 2.9.0 和 魔兽陪伴精灵 二开 2.9.0，游戏内执行 `/reload`，再正常退出并重启 魔兽陪伴精灵。角色快照仍使用 v3，传输码仍为 64×64，原有金币、等级历史、普通装备和确认结果协议不变。

## 2.7.0：角色阵营与种族

两版插件的角色快照升级为 `v=3`，新增必填字段 `faction` 和 `race`。
`faction` 仅接受 `Alliance`（联盟）、`Horde`（部落）、`Neutral`（中立）或 `null`；`race` 为非空的客户端本地化种族名，最多 48 个 UTF-8 字节，禁止控制字符，也可为 `null`。
数据不可读取时保留 `null`，桥接不会依据种族猜阵营。中立和未知分别处理，未知种族也不会沿用旧角色的数据。
当前状态、事件发生时的快照和 HTTP 返回均保留这两个字段，供 魔兽陪伴精灵 结合人设、阵营与种族生成对话。桥接状态页也显示阵营和种族。

本次需要一起更新正式服插件 2.7.0 / 无限服插件 1.4.0、桥接 2.7.0 和 魔兽陪伴精灵，再重新载入游戏插件并重启 魔兽陪伴精灵。旧 `v=1/2` 快照会被明确拒绝，不会自动回退。
网格大小、WCP1/WCF1 标识、512 字节帧和最多 504 字节 JSON 负载保持不变。

## 正常使用：只启动 魔兽陪伴精灵

2.2.0 起，魔兽陪伴精灵 主进程自动管理桥接。双击上层 `Start-WoWCompanion.cmd`，然后在 **设置 → 魔兽陪伴精灵** 开启陪伴连接即可。启动脚本的正常模式只启动 魔兽陪伴精灵，无需另外打开终端或运行桥接脚本。

魔兽陪伴精灵 先检查本机服务。没有服务时，它在隐藏窗口中启动 Python 子进程，等待健康检查成功，再读取角色状态。启动失败会显示错误，并按延迟重试。已经运行的兼容桥接会被复用，不会启动第二份。端口上是不兼容服务时会报错，不会停止那个进程。

关闭设置窗口不影响连接。关闭陪伴连接或退出 魔兽陪伴精灵，会停止 魔兽陪伴精灵 自己启动的子进程；再开启连接会重新启动。子进程通过 `--managed-stdin` 监测父进程管道，魔兽陪伴精灵 崩溃或被强制关闭后也会退出。复用的外部桥接仍由原启动方式管理，不随 魔兽陪伴精灵 关闭。

本次保留 **Python 3.10+** 本机依赖，没有把解码器改写为 JavaScript，也没有打包 Python 解释器。真实截图仍需 Windows。源码开发版支持 `airi` 与 `WOWAddons` 并列的目录布局；桌面打包配置通过 `extraResources` 包含桥接脚本。当前正式服插件 2.8.0 / WCP1、无限服插件 1.5.0 / WCF1，两者均使用 v3 快照。

更新后，先正常退出旧 魔兽陪伴精灵，再运行启动脚本。脚本提示 `already running` 时不会替换旧进程。已有模型、语音和金币账本继续使用原配置。

## 画面校准

默认截图区域左上角是屏幕物理坐标 `(8, 8)`，每格 `1` 物理像素，总大小 `64 × 64`。插件网格需完整可见。窗口模式、多显示器或插件移动位置后，在本机页面或 魔兽陪伴精灵 设置页修改 X/Y 和每格像素。

新版默认即使用 64×64 像素网格；在游戏输入 `/wowc compact` 或 `/wowc cell 1` 可恢复最小布局，桥接页每格像素推荐设为 `1`。缩小不改变数据容量和协议。更新修正物理像素缩放的插件后，旧版按放大画面填写的坐标和格宽需重新校准。

插件端已按屏幕物理高度换算 UI 单位，心跳会修复登录后较晚发生的 UI 缩放变化；颜色更新后会恢复像素吸附，兼容 NDui 的全局纹理钩子。桥接仍要求最终呈现在桌面上的网格没有被额外缩放。

点击“刷新预览”检查截图是否刚好包含 64 × 64 黑白网格。`x/y` 支持负数以覆盖主屏左侧或上方的显示器。显示缩放由 Windows DPI 感知处理，但游戏 UI 缩放、分辨率和 HDR 仍需在实际客户端验收。被遮挡、最小化或停止渲染时不保证可采集；超过 5 秒无新心跳会标记 `stale`。

**灰色或背景色混入网格、CRC 持续失败：**在确认坐标、格宽和遮挡无误后，进入游戏“系统 → 图形”，先切换到窗口模式并应用，再切回“全屏（窗口化）”并应用，选择显示器原生分辨率；然后输入 `/reload` 重建游戏布局，再重新校准并刷新预览。游戏内部报告的分辨率与 Windows 实际游戏客户区不一致，会使网格被再次拉伸。本机曾报告 2560×1440，但客户区实际为 2576×1460；重新应用显示模式并重载后恢复一致，64×64 单像素网格持续处于 `live`，正确读取等级 90、“银月城”，心跳持续递增。此次保存的采集配置为 `x=8、y=32、cellSize=1`，其他布局须按实际位置填写。如果仍无法可靠采集，可将游戏与桥接都恢复为每格 2 像素，继续核对分辨率和 HDR，而不是只放宽校验阈值。

正式服源码版自动启动和独立脚本都使用本目录的 `bridge-config.json`，保留已有校准。打包版使用 魔兽陪伴精灵 用户数据目录下的 `wow-companion-bridge/bridge-config.json`；首次运行能找到源码配置时复制一次，不覆盖已有配置。启动错误显示在 魔兽陪伴精灵 设置页，后台 Python 的错误输出仅在内存中保留末尾 4KB 用于诊断。两种启动方式使用相同的配置字段：

```json
{"x":8,"y":8,"cellSize":1,"pollMs":100,"paused":false}
```

## 已实现

- GDI 仅截图配置的网格区域，不访问 WoW 进程内存、文件内部结构或游戏输入。
- WCP1 帧头、长度、CRC16、UTF-8、JSON 类型及范围校验；不完整或损坏帧不触发事件。
- 金币快照：严格验证 v3 的本机账号标识、角色计数段、当前铜币余额和累计流入/流出，金额必须为非负安全整数。余额不可用时为 null。
- 角色状态：姓名、服务器、等级、职业、专精、阵营、种族、地图与区域、战斗、死亡、在线状态。
- 事件：`connected`、`level_up`、`zone`、`death`、`revive`、`combat_start`、`combat_end`、`offline`。
- 初次连接、角色切换、会话切换、画面过期恢复、暂停恢复只建立新基线；不把离线期间的等级变化当作刚发生的升级。
- `seq` 去重，`tick` 识别新心跳。相同帧反复可读也会在 5 秒后过期，避免最小化时的旧截图被当成实时状态。
- 地图 ID 为 0 或区域名称暂不可用时不触发区域通知，并保留最近有效区域用于比较；恢复原区域不重复提示。身份、会话、在线基线重建或演示切换会重置该比较基线。
- 内存中最多保留 200 个事件；不保存角色历史到磁盘。进程重启事件游标归零。
- 显式演示：升级、区域、死亡、复活、战斗；事件带 `demo: true`，状态为 `demo`。退出演示清空当前快照并等待真实帧。
- 本机校准页面、截图预览、暂停恢复、JSON API。

桥接本身不调用任何 AI 服务。魔兽陪伴精灵 负责模型、语音和角色反应；是否让角色主动说话由 魔兽陪伴精灵 端的陪伴规则控制。SavedVariables 由游戏插件保留作人工排查/后续导出；本服务当前实时入口只接受屏幕网格，未实现 SavedVariables 文件解析。

## HTTP 接口

只监听 `127.0.0.1`。`GET /health` 返回 `service: "wow-companion-bridge"`、`version: "2.3.0"`、对应的 `game` 和 `protocol`。无限服地址为 `http://127.0.0.1:18766/`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/status` | 状态、最新快照、最近事件、配置、错误 |
| `GET /api/events?after=N` | 读取 ID 大于 N 的事件，返回 `cursor` |
| `GET /api/frame.bmp` | 最近真实采集区域的 BMP；演示期间不生成虚假截图 |
| `POST /api/config` | 更新 x/y/cellSize/pollMs/paused，返回完整状态 |
| `POST /api/demo` | `{ "enabled": true, "action": "level_up" }`，action 可省略 |

所有写入仅接受 `application/json`，请求最大 4096 字节。网页来源只允许本机 HTTP(S) 与 `airi://local`；校验 Host 避免 DNS rebinding。原生 Electron main `fetch` 不带 Origin 可以使用。无需把接口暴露到局域网，也不需要 CORS 凭据。

`GET /api/status` 结构：

```text
status: live | stale | waiting | demo | paused
source: screen | demo
snapshot: null 或 WCP1 快照
lastSeen: null 或 UTC ISO 8601 时间字符串
ageSeconds: null 或距最新心跳的秒数
eventCursor: 进程内递增整数，重启归零
instanceId: 每次桥接进程启动生成的 UUID；变化时客户端应重置游标
events: [{id, type, timestamp, title, detail, snapshot, demo}]
config: {x, y, cellSize, pollMs, paused}
error: null 或中文诊断
protocol: WCP1
staleAfterSeconds: 5
```

不要仅根据快照是否存在判断在线：过期后会保留快照供用户核对，必须同时判断 `status === "live"`。演示数据也必须按 `source/status` 区分。

## WCP1 协议

64 列 × 64 行，行优先，每字节高位在前：黑为 0，白为 1。512 字节：

| 字节 | 内容 |
| --- | --- |
| 0–3 | ASCII `WCP1` |
| 4–5 | JSON UTF-8 字节长度，小端 uint16，最大 504 |
| 6–7 | JSON 负载 CRC16-CCITT，小端，初始 `0xffff`、多项式 `0x1021` |
| 8–511 | JSON 字节，余下补 0 |

字段：`v,session,seq,tick,guid,name,realm,level,class,spec,faction,race,map,zone,combat,dead,online,account,moneyEpoch,copper,earned,spent`。
JSON 快照版本 `v=3`，WCP1/WCF1 帧布局和 64×64 位网格不变。插件、桥接和 魔兽陪伴精灵 需一起更新；旧 v1/v2 快照会被拒绝。
`account` 为本机账号级保存标识，`moneyEpoch` 为角色计数段；后三个金额字段使用铜币整数。金币汇总及磁盘账本由 魔兽陪伴精灵 主进程管理，桥接只校验并传递。
`seq` 仅业务更新时增加，`tick` 每秒更新。`class` 是英文职业 token，`spec/map` 为数字 ID。
`faction/race` 必须明确存在；允许 `null` 表示不可用，不接受缺失字段。阵营为固定英文枚举，种族为客户端本地化名称；这两个字段彼此独立，不根据其一补全另一项。
