占用锁

POST /lock · /lock/release
占用期间这只宠物完全静止，动作接口只有持锁者能调
模拟联动演出的第一步（issue #122 第 4 项）：POST /lock 拿一个 lockId，这段时间这只宠物归你独占——它自己不动、也不弹气泡 （随机动画、自主走位、碎碎念、余额、工作状态一概让路）。
占用期间，本页其他卡片里的接口（投喂、点播动画、位置、抛掷、清空气泡） 必须带上这个编号，否则回 lock-required；带错编号回 lock-lost（附 cause：过期 / 已释放 / 被用户抢走）。本页会自动带上，不用手填。
取锁和续期是同一个接口：给 lockId 就是续期。续期是持锁者 每隔几秒要做一次的心跳——不续期的话，到点锁自己就没了。
用户优先：用户拖一下宠物、或把它隐藏/关闭，锁会立刻被撤掉，所以别把它当成能长期占着的东西。 没锁的时候那些接口连 lock 参数都不看，行为跟以前一模一样。
ms · 1000–1800000（1 秒–30 分钟）· 缺省 120000（2 分钟）· 续期时沿用上次

第三方投喂

POST /broadcast
不生成内容，只把给定文本搬进气泡；配图给池内名或自带地址
模拟宿主侧其他插件（如巡检类插件）调用 POST /broadcast： 不生成内容，只搬运。 配图两种形态二选一（issue #122 第 1 条）：给名称时只接受该桌宠条目表情包池内的名字 （pet/<素材根>-memes/ 独占 → 用户 memes/ → 包内 assets/memes/）， 下拉框只列磁盘上真实存在的图；给地址时是完整 URL、不查池。 两个都给会被判 bad-request。
时长可调、可关掉动画联动、可提前撤回——这三件事是 issue #122 第 5 条要的。 内容与频率由调用方自己负责：不设长度限制，也不限频；「清空气泡」只收起说话气泡， 正在播的动画、余额气泡、工作状态气泡都不动，没有气泡时也回 ok。
ms · 缺省 10000 · 0 = 不显示

点播动画

POST /anim
播池内名字（同右键「动作」菜单）或第三方自带的地址
两种形态二选一（issue #122 第 1 条）：给名字时必须是该宠物动画池里真实存在的 （下拉框列的就是池子），效果与右键菜单点「动作」完全一致——文字类先强制朝左的镜像修正、 移动类走真实位移；给地址时是第三方自带的素材，完整 URL、不查池， 消费端直接换源播一次、不走菜单语义（裸地址没有"是不是文字类 / 是不是移动类"这些属性）。 两个都给或都不给都会被判 bad-request。
点播是"插播一段"：播完回到正常动画链；display: both 时两端都会播。 要看回执请用下面那张「播放回执」卡片。
画面是浏览器从上传后的那个地址取回来的——能出画就说明服务真能访问它。 地址跨源（测试代理 8741 vs DSH 页面），代理给 /__uploads 补了 Access-Control-Allow-Origin 才能过。
可选。不指定就不动朝向（保持宠物当前朝向，不是回落 left）； 指定了就设成它，并优先于"文字类动画点播前强制朝左"那条镜像修正。

显示在哪端

POST /pet-display
只传宠物 id 与目标 display，层归属由宿主按 id 反查
模拟第三方调用 POST /pet-display：只传宠物 id 与目标 display，不用回传整段 pets——层归属（写 main-config.jsonc 还是 pet/<前缀>-config.json）由宿主按 id 反查。 桌面端与浏览器端的右键菜单「显示位置」走的就是它。
这管的是"哪个端"，不是屏幕坐标——屏幕坐标见同页的「位置与抛掷」。 这是持久配置写入，不是临时隐藏：选「都不」后这只宠物两端都不可见， 恢复入口是设置页的「显示在哪端」下拉框。返回体是改动后的成品聚合，本页据此刷新宠物清单。
